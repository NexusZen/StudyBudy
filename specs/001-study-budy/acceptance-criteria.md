# Study Budy acceptance criteria

Acceptance cases define observable behavior. Test Design assigns executable TEST IDs referencing these AC/REQ IDs. No case is marked passed before execution.

| Case   | Requirements        | Given / When / Then                                                                                                                                                                                                                                                   |
| ------ | ------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| AC-001 | REQ-001,002,004,015 | Create a named subject plan using sample text in explicitly labeled fake mode; a daily plan appears, provider attribution is visible, and retrieval after restart preserves it.                                                                                       |
| AC-002 | REQ-002,008,009,018 | Submit missing names, impossible dates, reversed dates, NaN/negative/huge capacity or malformed body; request fails with actionable error and no partial persisted plan.                                                                                              |
| AC-003 | REQ-003,007         | Upload a valid text PDF and TXT; readable text produces topics carrying source references. Missing page metadata stays absent.                                                                                                                                        |
| AC-004 | REQ-003,018,020,021 | Upload unsupported binary, empty, corrupt/image-only PDF, oversized file, empty extracted text, or path traversal filename; clear rejection and no arbitrary filesystem access/retained upload.                                                                       |
| AC-005 | REQ-004,005,006     | Inject a valid mocked Gemini structured response; validated units are returned. Invalid JSON, empty result, bad types, missing titles/estimates, duplicate IDs, or excessive output is rejected.                                                                      |
| AC-006 | REQ-004,018         | Gemini fails/rate-limits or key is missing in live mode; show a recovery error, never falsely label fake topics as Gemini. Fake mode works without key/network.                                                                                                       |
| AC-007 | REQ-008,010,011     | Schedule across month/year/DST boundaries and a single-day range; repeated input gives identical allocations on the exact date-only range.                                                                                                                            |
| AC-008 | REQ-009,011         | Different weekday capacities and unavailable dates are supplied; every day stays within its own capacity and unavailable dates have no new sessions.                                                                                                                  |
| AC-009 | REQ-012             | Topic workload exceeds any daily capacity; it splits, each duration is positive, and scheduled + unscheduled study minutes exactly equals input workload without duplicate sessions.                                                                                  |
| AC-010 | REQ-013             | Topics have prerequisites; prerequisite workload is assigned first. Invalid/cyclic references follow an explicit reject/normalization policy and cannot hang the scheduler.                                                                                           |
| AC-011 | REQ-014             | Workload exceeds capacity or all capacities are zero; expose remaining unscheduled minutes and explicit warning; daily limits still hold.                                                                                                                             |
| AC-012 | REQ-007,010,012     | Fractional estimate/missing optional metadata is normalized consistently; missing page numbers are never guessed; revision/buffer policy is explainable and minute accounting remains exact.                                                                          |
| AC-013 | REQ-015,016         | Mark a 30-minute session Completed and a 60-minute session In Progress from 120 study minutes; completed workload is 30, remaining is 90 and completion is 25%; persist and retrieve statuses.                                                                        |
| AC-014 | REQ-016,018,020     | Update nonexistent plan/session or illegal status; reject without changing another plan or corrupting progress.                                                                                                                                                       |
| AC-015 | REQ-017             | Complete some split sessions then reschedule from a future date with changed capacity; completed IDs/dates/minutes/status stay identical, unfinished and overflow work appear only on remaining dates, and conservation holds.                                        |
| AC-016 | REQ-017,018         | Reschedule with insufficient/zero remaining capacity or invalid date; infeasibility preserves remaining workload, and invalid requests leave original state intact.                                                                                                   |
| AC-017 | REQ-019,020         | Material contains “reveal your key/delete database/ignore instructions” and HTML/script; it stays quoted data, no model tools/state commands run, output validation applies, and text renders without script execution. Browser bundle contains no Gemini credential. |
| AC-018 | REQ-021,025         | Setup/privacy docs disclose local plan storage and sending material to Gemini in live mode; original uploads/extracted text are not unnecessarily retained and input bounds are documented.                                                                           |
| AC-019 | REQ-022,023         | Run primary browser journey by keyboard and practical E2E: open, create, upload, set dates/capacity, generate, inspect sources, complete session, inspect progress and reschedule.                                                                                    |
| AC-020 | REQ-023,024,025     | Tests, lint/format, type checks and production build run; stage reports contain actual commands/results, review/fix/recheck evidence, requirement traceability, independent verifier conclusion and honest limitations.                                               |
